**Foundational Thinking** drove tying the footer to session run state, not React `busy`. `busy` is also true during `resetAgent` and `switchExecutionMode`, which do not set `currentRun`.

**Layout**

Bottom chrome is a column. Transcript box, optional scroll hint, then command / model / input panel. `transcriptViewportRows` subtracts **6** rows in input mode (more in command/model). The scroll hint is outside that budget, so a one-line footer must bump the reserved chrome in all three modes or small terminals clip.

Default PR1 slot is a new row between scroll hint and bottom panel. `split-footer` on the renderer exists in OpenTUI but this repo uses `alternate-screen` only. Split footer is a wider alternative.
